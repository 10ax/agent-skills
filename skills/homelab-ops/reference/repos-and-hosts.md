# Which repo owns what

Depth for `homelab-ops`. Four repositories hold overlapping-looking things. Getting this wrong is the most common failure in this domain: a value is changed in one place and read from another, or a doc copy is edited while the live file keeps the old value.

## The map

| Repo | Local path | Owns | Nature |
|---|---|---|---|
| `10ax/homelab-config` | `~/Homelab/homelab-backup` | the homelab's **documentation and service configs**: `README.md` (machines + three rules), `docs/` (inventory, runbooks, network), `atlas/`, `odroid/`, `tools/` | reference, refreshed by **its own** `collect.sh` |
| `10ax/dotfiles` | `~/dotfiles` | **machine state** for atlas and elitebook: shells, KDE, ssh, systemd, opencode config, memory notes | generated by `collect.sh`, applied by `install.sh`, guarded by four test suites |
| `10ax/docker` | odroid `/root/docker` | the odroid's **compose stacks** and their stack docs | **public**; hand-written |
| `10ax/agent-skills` | `~/Personal/code/agent-skills` | these skills | hand-written |

Two *different* `collect.sh` scripts exist — `~/dotfiles/collect.sh` and `~/Homelab/homelab-backup/collect.sh` (different files, different md5). Do not assume a change to one applies to the other, and do not run the wrong one: the homelab one refreshes the docs and service configs, the dotfiles one refreshes machine state.

## The two collection scripts, briefly

**`~/Homelab/homelab-backup/collect.sh`** refreshes the docs and the `atlas/` + `odroid/` service configs from the live machines, and a `.githooks` pre-commit hook stamps the docs with the date. Docs that carry a `Last updated` line are generated: correct the source, re-run the collector, do not hand-edit the output.

**`~/dotfiles/collect.sh`** copies live machine state into `hosts/<host>/`, redacting secrets and recording the file modes git cannot store. Its contracts are the subject of the `dotfiles-collect` skill.

`elitebook` is a client, not a service host: its machine configuration belongs to `dotfiles-collect`, and it appears in homelab work only where it interacts with the services (streaming from atlas, KDE Connect, the LAN firewall).

## Working with the user's records

- A backlog item is a **memory of a symptom**, not a state. Check the live system before implementing it.
- When you change something a doc or the record asserts, refresh the record in the same task, or the next reader restores the old value.
- New open items go to `~/Documents/SecondBrain/000-Inbox/` in the vault's own format (Italian, frontmatter with `tags`, `creata`, `stato: da smistare`, `fonte`), never into `600-Backlog/`.
- Facts worth keeping across sessions go to the memory folder as one fact per file, with a pointer line in `MEMORY.md`.
